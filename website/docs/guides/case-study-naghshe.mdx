# Case Study: Naghshe — Spatial Search & a Generated Client

**Naghshe** ("نقشه" — map) is a tourism and heritage platform (database `yademan`): places of interest, virtual tours, events, and user comments. It is the best example of **spatial queries in Lesan** and of a workflow where the server **generates typed frontend functions** from its own declarations.

## What Makes It Interesting

- **GeoJSON fields on models** — every `place` has `center`, `area`, and `polygon` geometries validated by a shared `geoJSONStruct`.
- **Spatial search in an aggregation** — the `gets` act supports `$geoNear` (proximity, must be the first pipeline stage) and `$geoIntersects` (polygon/area containment) in a single client-driven pipeline.
- **Generated `"use server"` client functions** — `utils/actionGenerator.ts` reads the declared `ReqType` and scaffolds a typed API function per act (gets/get/count) for Next.js, keeping the frontend calls compile-checked against the backend schema.
- **Solar Hijri-aware filters** — an "antiquity" filter converts Gregorian years to the Jalali calendar to find buildings older than N years.

## Acts

Per-model `add` / `get` / `gets` / `count` / `update` / `remove`, plus relation-management acts (`updatePlaceRelations`, `removePlaceRelations`). The `place/gets` act is where the interesting code lives.

## Spatial search in one pipeline

The `gets` act builds a `$match` from plain filters, then prepends a `$geoNear` stage when the client asks for proximity search (since `$geoNear` must run first), and composes `$geoIntersects` for containment:

```ts
export const getsFn: ActFn = async (body) => {
  const { set, get } = body.details;
  const { page, limit, name, province, categoryIds, tagIds, polygon, area, near, maxDistance, antiquity } = set;

  const pipeline: Document[] = [];
  const matchConditions: Document = {};

  // --- GeoJSON containment: a place's polygon/area intersecting a drawn shape ---
  if (polygon) matchConditions.center = { $geoIntersects: { $geometry: polygon } };
  if (area)    matchConditions.area   = { $geoIntersects: { $geometry: area } };

  // --- Antiquity: construction year <= current Jalali year - age ---
  if (antiquity !== undefined) {
    const currentSolarYear = new Date().getFullYear() - 621;
    matchConditions.antiquity = { $lte: currentSolarYear - antiquity };
  }

  // --- Proximity: $geoNear must be the FIRST stage ---
  if (near) {
    const geoNearStage: Document = {
      $geoNear: {
        near,
        distanceField: "distance",
        spherical: true,
      },
    };
    if (maxDistance) geoNearStage.$geoNear.maxDistance = maxDistance;
    pipeline.push(geoNearStage);
  }

  if (Object.keys(matchConditions).length > 0) {
    pipeline.push({ $match: matchConditions });
  }

  pipeline.push({ $sort: { _id: -1 } });
  pipeline.push({ $skip: (page - 1) * limit });
  pipeline.push({ $limit: limit });

  return await place.aggregation({ pipeline, projection: get }).toArray();
};
```

## Generated client functions

The `actionGenerator.ts` script walks each model and writes a typed `"use server"` wrapper per act, importing the generated `ReqType` from `declarations/selectInp` — so a change to a validator on the server immediately breaks the frontend build until the caller is updated:

```ts
// generated for each model, e.g. src/place/gets.ts
"use server";
import { AppApi } from "@/services/api";
import { ReqType } from "@/types/declarations/selectInp";
import { cookies } from "next/headers";

export const gets = async ({ set, get }: ReqType["main"]["place"]["gets"]) => {
  const token = (await cookies()).get("token");
  return await AppApi().send(
    { service: "main", model: "place", act: "gets", details: { set, get } },
    { token: token?.value },
  );
};
```

:::info Takeaway
Naghshe shows two things: **MongoDB spatial operators compose cleanly with client-driven projections** (`$geoNear` + `$geoIntersects` inside a normal act), and **Lesan's generated declarations can drive code generation** on the client side — the frontend calls stay type-safe because they're produced from the same schema the server validates against.
:::
