# Case Study: Ziwound — Reports, Rate Limiting & Exports

**Ziwound** is a war-crimes documentation platform (database `gozaresh`): witnesses submit structured **reports** about incidents, backed by **documents**, tagged with locations, and cross-checked through **confirmations**. It is a good study in **guard rails** — rate limiting, role gates, text search — and in **non-CRUD acts** like statistics and file exports.

## What Makes It Interesting

- **Rate limiting as a `preAct` hook** — a small `RateLimiter` class with a `createRateLimitMiddleware` factory runs between `setUser` and `grantAccess`, keyed by user `_id`.
- **Non-CRUD acts** — `statistics`, `exportCSV`, and `exportPDF` are plain acts over the `report` model, so the client can ask for a filtered CSV or a dashboard aggregate without a separate endpoint stack.
- **Text indexes** — `createUserTextIndex` and `createBlogPostTextIndex` are created after model registration so `gets`/`exportCSV` can do `$text` search with relevance sorting.
- **Spatial filters** — `exportCSV` accepts `nearLng`/`nearLat` and builds a `$geoNear`-based match for "incidents near here".
- **Dot-notation relation filtering at scale** — the statistics act filters on `"hostileCountries._id"`, `"attackedProvinces._id"`, `"warCriminals._id"`, etc., all `$in` arrays of `ObjectId`.

## Models & Relations

| Model | Purpose | Notable relations |
|-------|---------|-------------------|
| `user` | reporters/admins | — |
| `country` / `province` / `city` | geography | many |
| `report` | the core incident document | `reporter`, `documents` (File[]), `tags`, `category`, `hostileCountries`, `attackedCountries`, `attackedProvinces`, `attackedCities`, `warCriminals` |
| `warCriminal` | named individuals implicated | `reports` |

| `blogPost` / `heroSlide` / `file` | site content | — |

The `report` model is a hub of many-to-many relations to countries and people — the frontend selects which to include in a `get` and Lesan embeds the snapshots:

## Acts

Per-model `add` / `get` / `gets` / `count` / `update` / `remove` / `updateRelations`, plus `report/statistics` and the export acts `report/exportCSV` and `report/exportPDF`.

## Rate limiting inside the pipeline

The limiter is a plain sliding-window counter keyed per user, and the middleware factory reads the current user from context:

```ts
export class RateLimiter {
  private requests: Map<string, number[]> = new Map();
  constructor(private limit: number, private windowMs: number) {}

  isAllowed(key: string): boolean {
    const now = Date.now();
    const timestamps = this.requests.get(key) || [];
    const valid = timestamps.filter((t) => now - t < this.windowMs);
    if (valid.length >= this.limit) return false;
    valid.push(now);
    this.requests.set(key, valid);
    return true;
  }
}

export const createRateLimitMiddleware = (limiter: RateLimiter) => {
  return () => {
    const { user: { _id } }: MyContext = coreApp.contextFns.getContextModel() as MyContext;
    if (!limiter.isAllowed(_id?.toString() || "anonymous")) {
      throw new Error("Rate limit exceeded. Please try again later.");
    }
  };
};
```

Wired into an act's `preAct` array, between authentication and authorization:

```ts
export const addSetup = () => {
  const rateLimitMiddleware = createRateLimitMiddleware(rateLimiter);
  return coreApp.acts.setAct({
    schema: "report",
    actName: "add",
    fn: addFn,
    preAct: [setTokens, setUser, rateLimitMiddleware, grantAccess({ levels: ["Manager", "Editor", "Ordinary"] })],
    validator: addValidator(),
    validationRunType: "create",
  });
};
```

The limiter instance lives at module scope in `mod.ts`, so every act that attaches the middleware shares one window:

```ts
export const rateLimiter = new RateLimiter(100, 60 * 1000); // 100 requests per minute
```

## Statistics & export as plain acts

`statistics` builds a `$match` from the same filter vocabulary as `gets` — including dot-notation relation `$in` — then a `$group`/`$project`:

```ts
export const statisticsFn: ActFn = async (body) => {
  const { set: filters } = body.details;
  const matchStage: Document = {};

  if (filters.status) matchStage.status = filters.status;
  if (filters.categoryId) matchStage["category._id"] = new ObjectId(filters.categoryId);
  if (filters.hostileCountryIds?.length) {
    matchStage["hostileCountries._id"] = {
      $in: filters.hostileCountryIds.map((id: string) => new ObjectId(id)),
    };
  }
  if (filters.warCriminalIds?.length) {
    matchStage["warCriminals._id"] = {
      $in: filters.warCriminalIds.map((id: string) => new ObjectId(id)),
    };
  }
  // ... createdAt range, priority, language ...

  const pipeline = [{ $match: matchStage }, { $group: { _id: "$status", count: { $sum: 1 } } }];
  return await report.aggregation({ pipeline }).toArray();
};
```

And `exportCSV` is just another act — it runs the same filters, fetches with `find`, serializes to CSV in the fn, and returns a string body the client can download:

```ts
export const exportCSVFn: ActFn = async (body) => {
  const { set } = body.details;
  // build the same $match as gets/statistics (including $geoNear near lng/lat)
  const rows = await report.find({ filters: match, projection: {} });
  return arrayToCSV(rows as Record<string, unknown>[]);
};
```

:::info Takeaway
Ziwound shows that **everything Lesan exposes is just another act**. Rate limiting is middleware composed into `preAct`, statistics and exports are plain fns over the same model, and relation-heavy filters work directly on the embedded snapshots with dot-notation `$in`.
:::
