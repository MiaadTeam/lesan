# removeTag

Deletes a **tag** by its `_id`. Only `Manager` and `Admin`. Deleting a tag that is still referenced by products is blocked by the ODM's relation guard — you must un-tag those products first.

:::note
**Import alias**
The code below imports the framework as `lesan` — that's the path alias this repo's app uses (see [Project Layout](/docs/tutorials/procurement-workflow/project-layout)). In your own project, import from `@hemedani/lesan` (npm/Bun) or `jsr:@hemedani/lesan` (Deno) instead.
:::

## Registration (`mod.ts`)

```ts
import { grantAccess, setTokens, setUser } from "@lib";
import { coreApp } from "../../../mod.ts";
import { removeTagFn } from "./removeTag.fn.ts";
import { removeTagValidator } from "./removeTag.val.ts";

export const removeTagSetup = () =>
  coreApp.acts.setAct({
    schema: "tag",
    actName: "removeTag",
    preAct: [setTokens, setUser, grantAccess([{ roles: ["Manager", "Admin"] }])],
    validator: removeTagValidator(),
    fn: removeTagFn,
  });
```

## The validator (`removeTag.val.ts`)

```ts
import { object, objectIdValidation } from "lesan";
import { selectStruct } from "../../../mod.ts";
import { activeRoleMixin } from "@lib";

export const removeTagValidator = () => {
  return object({
    set: object({
      ...activeRoleMixin,
      _id: objectIdValidation,
    }),
    get: selectStruct("tag", 1),
  });
};
```

`set` is `activeRoleId` + `_id`. `get` is depth 1.

## The implementation (`removeTag.fn.ts`)

```ts
import { type ActFn, ObjectId } from "lesan";
import { tag } from "../../../mod.ts";
import { throwError } from "@lib";

export const removeTagFn: ActFn = async (body) => {
  const {
    set: { _id },
  } = body.details;

  const removed = await tag.deleteOne({
    filter: { _id: new ObjectId(_id as string) },
  });

  !removed && throwError("tag not found");
  return removed;
};
```

1. `tag.deleteOne` removes the document.
2. `!removed && throwError("tag not found")` errors on a miss.

The interesting part is what `deleteOne` does *behind the scenes*. The product model defines `tags` with `relatedRelations: { products: ... }`, so every tag carries a reverse `products` back-reference. `deleteOne` checks that reverse map first: if any product still points at this tag, deletion is refused (see the guard error below) — you can't orphan embedded references.

## In the workflow

The cleanup act for tag reference data. Products can only be created and linked to existing tags, so `removeTag` is typically used on tags that were created by mistake or are no longer in use.

- [tag model](/docs/tutorials/procurement-workflow/models/tag)
- Sibling acts: [addTag](/docs/tutorials/procurement-workflow/catalog/add-tag), [getTags](/docs/tutorials/procurement-workflow/catalog/get-tags), [updateTag](/docs/tutorials/procurement-workflow/catalog/update-tag)

## Run it

```bash
curl http://localhost:1380/lesan \
  -H "Content-Type: application/json" \
  -H "token: <jwt>" \
  -d '{
    "model": "tag",
    "act": "removeTag",
    "details": {
      "set": { "activeRoleId": "ghost-role", "_id": "<tagId>" },
      "get": { "_id": 1, "name": 1 }
    }
  }'
```

## Errors & fixes

| Error | Meaning | Fix |
|-------|---------|-----|
| `tag not found` | No tag has that `_id`. | Check the id. |
| `please clear below relations status before deletion: ...` | Products still reference this tag. | Remove the tag from each product via [updateProductRelations](/docs/tutorials/procurement-workflow/catalog/update-product-relations) (send the product's `tags` array without this id), then delete again. |
| `activeRoleId is required` | No `activeRoleId` in `set`. | Add it (ghost: any string, e.g. `"ghost-role"`). |
| `Active role not found` | `activeRoleId` isn't one of the user's roles. | Pass a real `roleId`. |
| `You cant do this` | Active role isn't `Manager`/`Admin` (or ghost). | Elevate the role or use the ghost token. |
| superstruct "expected ObjectId-like string" | `_id` isn't a valid ObjectId. | Send the 24-hex id string. |
